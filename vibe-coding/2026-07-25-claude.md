## 1. User request

Please help me build _QDVC Tadaima_, a Python-based GTK4 application that helps users look at photos on their filesystem.

This application follows the specification here - https://github.com/qdvc-apps/qdvc-python-gtk-app-specification - please be sure that you discard any existing version of this specification from your caches and filesystem, and fetch a fresh copy for inspection. It deviates in two important ways:

1. There is no GTK3 version implemented at this stage;
2. There is no concept of a workspace of plaintext serialisable files. More on that below.

QDVC Tadaima operates on the basis of folders that the user has explictly added to the Scanned folders list (configured in app main menu --> Scanned folders). It does not attempt to access any other folders. Even those folders, it **STRICTLY** only ever accesses in read-only mode, making no changes to any files therein.

QDVC Tadaima scans for JPEG, HEIC, PNG for now. We might add more formats later.

QDVC Tadaima has a master-detail layout.

### Master (sidebar)

The "master" (sidebar) is a folder hierarchy, reflecting the actual hierarchy of the computer's filesystem, filtered down to the pathways to the folders that are on the scanned folders list. For instance if the user has added the following:

- `/home/james/Desktop/holiday-photos-copenhagen`
- `/home/james/wedding-photos`
- `/home/james/some-project/project/project-diagrams`

Then the hierarchy displays `home`, but only with one subfolder, `james`. Then that one subfolder, `james`, is listed as having 3 subfolders - `Desktop`, `wedding-photos`, `some-project` - even if there are other subfolders on the actual filesystem.

Each folder and subfolder has the regular folder icon by default. But if it is a folder that contains images at the root of its directory, then the icon is updated to be a square image of a crop of one of those pictures. The square image should be the same size as the regular folder icon, so that folders with immediate image children do not have a different layout in the sidebar compared to folders without immediate image children.

Each folder and subfolder displays a count of how many child, grandchild, ... nth-level-great-grandchild images are contained therein. This count is displayed on the right-hand side of the sidebar against each folder and subfolder.

An important feature is that the user can right click any folder or subfolder, which pulls up a menu. One item in the menu is **Locate on disk**, which shows where that folder is in the filesystem. But a very special item is **Focus on folder**. This changes the layout of the sidebar. The chosen folder becomes the root of the hierarchy (not listed first though), whilst preserving the hierarchy within it. Its parent, grandparent, ... ancestor folders are displayed as a flat list above it, in italics, for example:

```
_/_                            (2,000)
_home_                         (2,000)
_james_                        (2,000)
**Desktop**                      (956)
- holiday-photos-copenhagen      (950)
    - nyhavn                     (200)
        - boats                   (23)
    - rundetarn                  (125)
    - amalienborg-palace          (95)
    - train-to-malmoe            (123)
```

Here, **Desktop** is the focused folder, so it is in bold. The hierarchy above it is flattened (`/home/james`), but the hierarchy within it is not - it is just less "buried" within the hierarchy.

Clicking on any of the flattened folders (e.g., `james`, `home`) sets that as the new focused folder. Clicking on the top level is functionally the same as not having a focus. In other words, that's the default, **/** as the focused folder.

Note 1: This sidebar must be resizable.

Note 2: This is a standard GTK4 libadwaita sidebar, which by default has comically wide padding, as if for a tablet. QDVC Tadaima is opinionated in that it does not believe in this nonsense; it is optimised for traditional laptops and workstations. The padding should be reduced to be quite tight - let's call this the **Compact** setting for **Density** - this is the default in QDVC Tadaima. But in the application settings, allow the user to set it to the default GTK4 libadwaita padding - let's call this the **Rleaxed** setting for **Density**.

### Detail (thumbnails)

The main view is the photos. For selected folder in the sidebar, its child photos are displayed as thumbnails (each with a small drop shadow).

Hovering over one of the thumbnails changes the cursor to the "link" hand cursor (as one would see if hovering over a hyperlink).

Clicking on one of the thumbnails selects it (and it shows it with a selection border). Double-clicking it makes it fill the entire window (replacing both the master-sidebar and detail-thumbnails). A headerbar icon to go back (top-left corner), or hitting `Esc` on the keyboard, takes the user back to the normal master-detail view, with the selected thumbnail still selected.

### Indexing and thumbnails

Indexes and thumbnails are generated into a caches folder. Use XDG_CACHE_HOME unless you feel there's a better option.

For each of the scanned folders, the app scans for changes on launch (quietly, non-blocking, in the background).

New files are scanned and their thumbnail is generated at the following sizes:

- Square (if and only if chosen for the sidebar icon)
- Thumbnail (let's say max. 500px for height and max. 500px for width for now)
- Screen (let's say max. 2000px for height and max. 2000px for width for now)

The magic numbers of 500 for thumbnail size and 2000 for screen size should be saved as constants, we might revisit those later.

In the app's main menu, there should be an option to see the cache status and to force a regenerate of all caches across all scanned folders.
